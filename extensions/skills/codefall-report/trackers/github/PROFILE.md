# Tracker profile: github

**Status:** supported.

GitHub Issues, in the project's own repository — `github.issuesRepo` in `.codefall/settings.json`,
the one tracker a verb files on, per *Who is authoritative for what* in
`../../../../../.codefall/shared/workflow.md`. **The bug report is canonical.** This profile creates
and refreshes one issue generated from it; nothing here holds a fact the document does not.

## Preconditions

`gh` authenticated with `repo` scope. When it is not, **the report is still written**: give the user
`gh auth login`, say the mirror is pending, and stop the mirror there.

## Issue shape

One issue per report, no sub-issues.

```
Title:  BUG-012: Declined card empties the cart
```

```markdown
<!-- Generated by /codefall-report from docs/bugs/BUG-012-declined-card-empties-cart.md. Edits here are overwritten. -->

**Report:** [docs/bugs/BUG-012-declined-card-empties-cart.md](../blob/main/docs/bugs/BUG-012-declined-card-empties-cart.md)
**Severity:** major · **Reproduced:** Yes — 2026-09-28, at a1b2c3d

<the Summary, verbatim>

## Steps to reproduce
<verbatim>

## Expected result
<verbatim>

## Actual result
<verbatim>

## Evidence
- docs/bugs/BUG-012-declined-card-empties-cart/reporter-01-empty-cart.png — from the reporter

## Acceptance criteria
<verbatim>
```

**`gh` cannot upload images**, so evidence is listed by repository path and never embedded. The
Environment, Reproduction, Regression, and Open questions sections are not copied down; the link is
one click.

**The title carries the identifier**, which is how a later run finds the issue. Never retitle it by
hand.

## Labels

This profile invents no labels. It applies:

- `bug`, when the repository has it — GitHub creates it in every new repository;
- `draft`, while the report says `Draft`, created as `codefall-specify`'s profile creates it:

  ```bash
  gh label create "draft" --color "BFBFBF" \
    --description "Specification incomplete — spec is still Draft" --force
  ```

- a severity label, only when the repository already has one that matches the report's severity.

```bash
gh label list --json name --jq '.[].name'
```

## Searching for duplicates

```bash
gh issue list --search "<keywords>" --state all \
  --json number,title,state,url,labels --limit 10
```

## Creating

```bash
gh issue create --title "BUG-012: Declined card empties the cart" \
  --body-file <issue-body> --label bug
```

Use `--body-file`: the body carries quotes, parentheses, and newlines. Then write the number into the
report's `**Issue:**` row. The `blob/main` link resolves once the report's pull request merges, and
the pull request carries `Relates to #<issue>` until then.

## Adopting an issue the reporter filed

When the run started from an existing issue, that issue is the mirror; **do not open a second.** Its
title and body are the reporter's and are never overwritten. Post the generated body as a comment
instead, and write the issue's number into the `**Issue:**` row:

```bash
gh issue comment <number> --body-file <issue-body>
```

## Refreshing

Read the number from the `**Issue:**` row, regenerate the body, and write it back:

```bash
gh issue edit <number> --body-file <regenerated-body>
```

On an adopted issue, edit the comment carrying the generated-by marker instead:

```bash
gh api repos/<owner>/<repo>/issues/<number>/comments \
  --jq '.[] | select(.body | startswith("<!-- Generated by /codefall-report")) | .id'
gh api -X PATCH repos/<owner>/<repo>/issues/comments/<id> -F body=@<regenerated-body>
```

Reconcile `draft` against the report's status. **Never reconcile in the other direction**: a body
that differs from the report is a hand edit about to be overwritten, and the user is told so.

## Archiving

Regenerate the body with the archived status, path, and reason line, then ask whether to close the
issue. On yes:

```bash
gh issue close <number> --reason "not planned" --comment "<the reason line>"
```

Never close an issue without asking.

## Work state

The issue closes when the fix merges, not before. `codefall-implement` puts `Fixes #<issue>` in the
body of the pull request that carries the fix, so GitHub closes the issue at the human's merge. This
profile never closes an issue for a fix.
