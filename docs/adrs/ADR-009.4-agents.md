# ADR-009.4: Agents

## Status

Accepted — 2026-09-28

## Context

ADR-009.3 made four decisions. Three of them are about the project: how a harness is called, how
the script applies it, and what the findings schema may say. The fourth, that `codefall-equip` sets
a harness up only from inside that harness, is procedure in one skill. It also blocked the ordinary
case of setting codex up from a Claude Code session, when all that is being written is settings.
This record carries ADR-009.3 forward without the fourth decision; how equip helps a person find a
harness's parameters is the skill's to say.

The rest of this context is ADR-009.3's.

ADR-009.2 settled who codefall reaches for: an `agents` list keyed by the harness the session is
running in, each entry holding a `review` list and a `consult` list of agents, each a `harness` and
an optional `model`. It said nothing about how a harness is started once a list names it, because
until the first run through Bedrock nothing needed saying: `run-agent.sh` passed `--model` and the
read-only flags, and the harness did the rest.

The first run through Bedrock failed every time, and a direct call from a terminal succeeded every
time. Codex reaches Bedrock through the AWS SDK for Rust, which could not refresh the `aws login`
session on the machine while the AWS CLI could; the interactive shell had a `codex` function that
ran `aws configure export-credentials` first, and the script, being bash, never saw it. Two more
things surfaced on the way. The findings schema's `if`/`then` clause, which Muse's schema flag had
already rejected, is rejected by Bedrock's structured output too. And a headless codex run loaded
the project's session-start hooks and followed them into a refresh instead of answering.

Underneath all three was one gap: nothing in a project could say how a harness is called. The model
string is part of it, and it is easy to get wrong: the same model is `gpt-6-astra` direct,
`us.openai.gpt-6-astra` on Bedrock, and `amazon-bedrock/us.openai.gpt-6-astra` in OpenCode.

## Decision

### `harnessConfig` says how a harness is called

`.codefall/settings.json` carries an optional top-level `harnessConfig` object, keyed by name. A key
that is one of the five harness names configures that harness. Any other key is a variant whose
`harness` field names the binary, so a project can call codex two ways. A block may carry
`modelFlag`, the flag the model is passed with (default `--model`); `provider`, the harness's own
provider name; `args`, extra arguments appended as given; and `env`, a shell command whose standard
output is evaluated before the harness starts, so its `export` lines take effect.

```json
"harnessConfig": {
  "codex": {
    "provider": "amazon-bedrock-runtime",
    "args": ["-c", "model_reasoning_effort=high"],
    "env": "aws configure export-credentials --format env"
  },
  "codex-direct": {
    "harness": "codex",
    "args": ["-c", "model_reasoning_effort=high"]
  }
}
```

A list item's `harness` is the lookup key, and so is the harness in a `via=` value:
`{ "harness": "codex-direct", "model": "gpt-6-astra" }` and `via=codex-direct:gpt-6-astra` both run
codex the second way. A list item carries nothing else: the block is where how-to-call lives, once
per harness, and a second provider for the same harness is a second block. A harness name with no
block runs bare, as it always has.

### The script applies it

`run-agent.sh` reads the block with jq when settings and jq are present, turns `provider` into the
harness's own switch (codex's `-c model_provider=`, Claude Code's `CLAUDE_CODE_USE_*` variables,
OpenCode's `provider/model` form; Muse and agy have no switch and refuse the field), appends `args`,
and evaluates the `env` command inside the run's timeout. Every harness with a switch for its hooks
runs with them off: a run that proposes and never edits has no use for the project's session hooks,
and one was seen to follow them into a refresh.

### The schema stops saying what only some validators accept

The findings schema's `if`/`then` clause, which made `reason` required on a dismissed finding, is
removed, and triage asks for the reason before it writes a dismissal. A rule the schema cannot state
in a form every harness accepts belongs where it is applied.

## Alternatives

**Provider, args, and env on each list item.** Expressible, and repeated wherever the same harness
appears; the script reads no settings, so the skill would have had to pass them as flags on every
call. Set aside for one block per harness, with a variant for a second way to call the same one.

**A per-user file for the block.** The credential command is about a machine, but the provider is
the project's choice, and a variant covers the person who reaches the same harness another way. Set
aside because ADR-009 already keeps agents in the project's file.

**Doctor probing every agent.** Doctor runs nothing a project declares, and says so. Set aside for
equip's proof, which runs the one agent being set up, once, with the user watching.

## Consequences

- **A project says how each harness is called, once.** A person who cannot run the configured
  harness the configured way reads one block to see why, and a variant is one more block.
- **The script reads settings again, for one thing.** ADR-009.2 took the settings read out; this
  puts a narrow one back, optional, keyed by the harness the caller already resolved.
- **`via=` accepts a block key.** `via=codex-direct` is exactly what the file says, as
  `via=codex:gpt-5-codex` was.
- **Hooks are off for every headless run that has a switch.** A project's session hooks stop
  running under a reviewer; Muse and agy keep theirs until they gain a switch.
- **The findings schema is weaker on paper and the same in practice.** Triage holds the rule.
